## 0편 (트위터 스레드, 9/4 직후 선공개)
**"팬페이지 하나 만들었을 뿐인데 — 14일간의 기록"**
- 결과 숫자 3개 + 스크린샷 6장 + 블로그 예고. 시리즈의 트레일러 역할.

## 1편 — 기획: 데이터가 시킨 대로 만들기
- 시작점: 요즘IT의 Fable 활용 기사 → "나도 큰 일감에 써보자" (수미상관 포인트)
- 콘서트 예매자 통계(여성 95%+, 10~20대 80%)에서 도출한 설계 전제 3가지
- 바이럴 루프 설계: 테스트 → 카드 → 인증 → 유입 → 904 목표
- AI와의 역할 분담: "시키기"가 아니라 "상의하기" — 기획 대화 실례 2~3개
- 💡 훅: "AI가 낸 아이디어를 내가 뒤집은 순간들" (하트 프레임 → 폴라로이드 등)

## 2편 — 개발: 하루에 기능 9개가 나오는 워크플로
- AI 페어 워크플로 공개: 수정 → 빌드 검증 → E2E → 커밋 사이클
- 하이라이트 3개 (기술 깊이 증명):
  1. 유형 분포 쏠림 → 243개 전 조합 시뮬레이션 → 대표점 분류로 균등화
  2. iOS에서 CSS 애니메이션 멈춤 → requestAnimationFrame 전환기
  3. 비속어 필터의 오탐과 싸우기 ("일찍 자지 마"를 살려라)
- 💡 훅: 트러블슈팅 표 (worklog에서 발췌)

## 3편 — 배포와 운영: 0원으로 팬덤 트래픽 버티기
- Supabase RLS로 관리자 권한을 DB 레벨에서 거는 법
- AI 비용 방어 3종: 캐싱 / 레이트리밋 / 폴백
- 사진 212장을 서버비 0원으로: 핫링크 전략과 CORS의 벽 (위버스 vs 트위터)
- 실시간(WebSocket) 붙이고 오히려 요청 수가 줄어든 이야기
- 💡 훅: "17MB짜리 페이지의 Vercel 청구서는 0원" 네트워크 탭 스크린샷

## 4편 — 결과와 회고 (조회수 에이스, 9/4 이후)
- 실측 공개: 방문 N / 테스트 완료율 N% / 메시지 전환율 N% / 904 달성 여부
- 콘텐츠 2종(사진드컵 vs 유형테스트) 전환율 비교 — 퍼널 데이터 분석

- 잘한 것 / 다시 한다면 / v2(플랫폼화) 예고
