## 1. 배경 — 왜 이 방향인가

최근 콘서트(부산/서울) 예매자 통계 기준 팬층은 **여성 94~98%, 10대~20대 초반이 약 80%**.
주 활동 무대는 **트위터 + 위버스** (위버스 비중이 생각보다 큼). 친목 문화가 강함.

여기서 나온 설계 전제 3가지:

1. **모바일 온리** — 이 연령대는 PC가 없다. 참여·이미지 저장·공유 전부 폰 기준으로 설계.
2. **위버스는 링크가 아니라 이미지로 돈다** — 카드 이미지 자체에 페이지 주소(QR/URL)가 박혀 있어야 유입이 생김. 링크 클릭을 기대하지 않는다.
3. **친목 = 대화 소재 제공** — 기능이 "너는 뭐 나왔어?"라는 대화를 만들면 홍보는 팬들이 대신 한다.

## 2. 핵심 루프

```
[트위터/위버스에서 친구 카드 발견]
        ↓
  테스트 하러 유입 → 5문항 오프 성격 테스트 (비용 0, 즉시 결과)
        ↓
  결과: 유형 + 성호 파트 + 이미지
        ↓
  축하 메시지 남기면 → 닉네임·순번 박힌 "완성 카드" 획득 (904 목표에 +1)
        ↓
  카드 저장 → 트위터/위버스 인증 ("다음은 너 차례 @친구")
        ↓
  친구 유입 (루프 반복)
```

메시지 작성이 테스트의 **보상 조건**이 되는 게 핵심 — 테스트만 하고 나가는 사람을 롤링페이퍼 참여자로 전환한다.

## 3. 기능 명세

### 3.1 오프 성격 테스트 ("성호 생일날에 난?")

- 5문항, 2축(덕질 온도 × 덕질 스타일), 결과 6유형
- 로직은 고정 규칙(점수 합산) — **API 비용 0원, 결과 즉시**
- 문항·유형은 `config/quiz.ts` 한 파일에서 수정 가능하게 만들 예정 (주리가 언제든 문구 교체)

#### 문항 초안 ✏️ (주리 수정 예정)

1. 성호 생일날에 난? — ①생카 간다(혼자서) ②친구들이랑 같이 간다 ③집에서 홈파티
2. 너무 바쁜데 생카를 갈까 말까? — ①알바 빼고 간다 ②그래도 알바는 해야지.. (퇴근하고 감)
3. 신곡이 나왔다. 나는? — ①숨스밍 돌리며 조용히 눈물 ②트위터 실시간 감상 도배 ③친구 불러서 뮤비 정주행
4. 콘서트 티켓팅 성공! 내 자리는? — ①성호만 보이면 어디든 ②무조건 앞자리 눈맞춤 ③친구랑 같이 앉는 게 최우선
5. 성호가 위버스에 글을 올렸다 — ①몰래 백만 번 다시 읽기 ②광속 댓글 1등 노리기 ③단톡방에 공유부터

### 3.2 결과 화면 & 완성 카드

결과 화면 구성(위→아래): **유형 이름 → 유형 이미지(=직캠 썸네일, 누르면 직캠으로 이동) → 어울리는 성호 파트(곡명 + 가사 한 줄) → 유형 설명 2~3줄 → "직캠 보러가기 ▶" 버튼**.

**가사 인용 규칙** (2026-08-20 결정):
- 유형당 **딱 한 줄**, 반드시 곡명 표기 (예: `널 붙잡으러 갈거야 — Viral`)
- 전체 가사·연속 인용 금지. 비영리 + 출처 표기 + 기존 "요청 시 즉시 비공개" 고지가 안전장치
- 링크는 저작물 복제가 아니므로 유튜브 직캠 링크는 자유롭게 사용 가능

**직캠 연동** (2026-08-20 결정):
- 유형 이미지는 기본적으로 **직캠 유튜브 썸네일 자동 사용** (`img.youtube.com/vi/<영상ID>/...` — 직캠 URL만 넣으면 썸네일은 공짜)
- 썸네일 클릭 → 직캠으로 이동. 팬덤의 직캠 조회수 총공 문화와 연결되는 유입/체류 포인트
- 원하면 유형별 커스텀 이미지로 교체 가능 (직캠 썸네일이 별로인 유형만 갈아끼우기)

**카드 이미지 vs 결과 페이지의 역할 분리**:
- **저장되는 카드 이미지** (공유용): 유형 + 가사 한 줄 + 닉네임 + `#0134번째 원도어` 순번 + 페이지 URL — 이미지 속 링크는 눌리지 않으므로 직캠 버튼은 넣지 않음
- **결과 페이지** (체류용): 위 전부 + 직캠 썸네일/버튼 + (선택) AI 한 줄 코멘트

- 축하 메시지를 남기면 → **완성 카드** 생성 (닉네임·순번은 메시지 작성자에게만)
- 공유 기본 문구: "나는 ○○형 원도어래 🎂 다음은 너 차례 → (링크)"
- **리캡 카드도 같은 카드 디자인 시스템으로** 통일 — 테스트 카드가 템플릿의 첫 적용, 리캡 카드가 두 번째.

**유형 데이터 구조** (`config/quiz.ts` — 주리가 채울 칸):

```ts
{
  name: "저세상 텐션 올콘형",     // ✏️ 밈으로 교체
  description: "...",             // 유형 설명 2~3줄
  song: "Viral",                  // ✏️ 곡명
  lyricLine: "널 붙잡으러 갈거야", // ✏️ 가사 딱 한 줄
  fancamUrl: "https://youtu.be/...", // ✏️ 직캠 링크 (썸네일 자동 추출)
  customImage: null,              // (선택) 썸네일 대신 쓸 이미지
}
```

### 3.6 AI 사용처 (경력 포인트)

| 사용처 | 방식 | 비용 설계 |
|---|---|---|
| 완성 카드 한 줄 코멘트 | 메시지+유형 → 1문장 생성 (Haiku급) | 카드 생성 시 1회, 레이트리밋 |
| 생일 리캡 카드 | 전체 메시지 요약 | **하루 1회 배치 생성 + 캐싱** (방문자 클릭마다 호출 ❌) |
| 메시지 모더레이션 | 1차 단어필터(현행) → 2차 LLM 심사 | 걸린 것만 2차로 보냄 |

> 이력서 문장 목표: "LLM 큐레이션/모더레이션 파이프라인을 설계하고, 캐싱·배치로 일 운영비 N원 수준으로 최적화. 실사용자 N명."

## 6. 결정 기록

- AI 메시지 톤 분석 → **상황 테스트로 변경** (주리 제안): 선택지 자체가 대화 소재가 되고, 결과(성호 파트)가 아티스트 홍보로 이어짐. 테스트 로직 무비용이라 AI는 가치가 높은 지점(코멘트·리캡·모더레이션)에만 투입.
- "AI가 뽑은 오늘의 메시지"는 보류 — 하트 랭킹이 비슷한 역할을 더 싸게 함.
- 가사는 유형당 한 줄 + 곡명 표기만 (전체 인용 금지). 유튜브 직캠 링크는 자유 — 링크는 저작물 복제가 아님.
- 유형 이미지 = 직캠 썸네일 기본 (클릭 시 직캠 이동). 직캠 조회수 문화와 연결.
