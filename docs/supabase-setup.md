# Supabase 연결하기 (처음 하는 사람용, 약 30분)

> 목표: 지금은 새로고침하면 사라지는 롤링페이퍼 메시지를, **진짜로 저장되게** 만들기.
> 코드는 이미 다 짜여 있어요. 이 문서는 순수하게 **설정**만 합니다.

---

## 시작 전에 알아둘 것

**Supabase가 뭔가요?**
쉽게 말해 "클라우드에 있는 데이터베이스 + 그걸 웹에서 바로 쓸 수 있게 해주는 껍데기"예요.
원래 이런 걸 하려면 서버를 따로 만들어야 하는데, Supabase는 그 서버 부분을 대신 해줍니다.
우리 프로젝트에서는 **롤링페이퍼 메시지를 담아두는 통** 역할만 합니다.

**돈 드나요?** 무료 플랜으로 충분합니다. 카드 등록도 필요 없어요.

**앞으로 나올 세 가지 값** — 이것만 헷갈리지 않으면 됩니다.

| 이름 | 생김새 | 어디에 쓰나 | 공개돼도 되나 |
|---|---|---|---|
| Project URL | `https://abcd1234.supabase.co` | `.env.local` | ✅ 괜찮음 |
| Publishable key | `sb_publishable_...` | `.env.local` | ✅ 괜찮음 (원래 브라우저에 노출되는 용도) |
| Database password | 본인이 정하는 비밀번호 | **아무데도 안 씀** (나중에 필요할 수 있음) | ❌ 절대 공개 금지 |

> 💡 `sb_secret_...` 로 시작하는 키도 보일 텐데, **그건 절대 쓰지 마세요.** 우리 페이지는 브라우저에서 직접 DB에 붙는 구조라 secret 키를 넣으면 그대로 털립니다.

---

## STEP 1 — 계정 만들기 (3분)

1. [supabase.com](https://supabase.com) 접속 → 우측 상단 **Start your project**
2. **Continue with GitHub** 을 고르세요.
   - 깃허브 계정이 없다면 이 참에 만드세요. 어차피 STEP 6(배포)에서 필요합니다.
   - 이메일 가입도 되지만, 나중에 Vercel 배포할 때 깃허브가 또 필요해서 지금 만드는 게 이득이에요.
3. 권한 승인(Authorize) 누르면 끝.

---

## STEP 2 — 프로젝트 만들기 (5분, 대부분 기다리는 시간)

**New project** 를 누르면 입력창이 나옵니다.

| 항목 | 뭘 넣나 |
|---|---|
| **Name** | `bday-recap` (아무거나 상관없음) |
| **Database Password** | **Generate a password** 버튼을 눌러 자동 생성 → 나온 값을 메모장/비번관리자에 복사해두세요 |
| **Region** | **Northeast Asia (Seoul)** ⭐ |
| **Plan** | Free |

> ⚠️ **Region은 꼭 Seoul로 하세요.** 팬들이 대부분 한국에서 접속할 텐데, 미국 리전으로 잡으면 메시지 남길 때마다 눈에 띄게 버벅입니다. 나중에 못 바꾸고 프로젝트를 새로 만들어야 해요.

> ⚠️ **Database Password는 지금 복사해두세요.** 창을 닫으면 다시 볼 수 없습니다. (잊어버려도 재설정은 가능하지만 번거로워요.) 우리 코드에서는 안 쓰지만, 나중에 DB에 직접 접속할 일이 생기면 필요합니다.

**Create new project** 누르고 **2~3분 기다립니다.** 화면에 초록 점이 뜨고 "Project is ready"가 되면 완료.

---

## STEP 3 — 테이블 만들기 (2분)

메시지를 담을 표를 만드는 단계입니다. 직접 타이핑할 필요 없이 **복붙만** 하면 돼요.

1. 왼쪽 사이드바에서 **SQL Editor** 클릭
2. **New query** 클릭
3. 프로젝트 폴더의 `sql/schema.sql` 파일을 열어서 **내용 전체를 복사** → 편집창에 붙여넣기
4. 우측 하단 **Run** 클릭 (또는 `Ctrl + Enter`)
5. 아래에 `Success. No rows returned` 가 뜨면 성공 ✅

> "No rows returned"는 에러가 아닙니다. "표를 만들었고, 돌려줄 데이터는 없다"는 뜻이라 정상이에요.

**확인해보기**: 왼쪽 사이드바 **Table Editor** → `messages` 테이블이 보이고, 컬럼이 `id / nickname / content / created_at` 네 개면 제대로 된 겁니다.

---

## STEP 4 — 키 두 개 복사하기 (2분)

1. 왼쪽 사이드바 맨 아래 **Project Settings**(⚙️) → **API Keys**
2. 여기서 두 개를 복사합니다:
   - **Project URL** — `https://xxxxx.supabase.co`
   - **Publishable key** — `sb_publishable_...` 로 시작하는 값

> 화면에 **Legacy API Keys** 탭이 따로 있고 거기 `anon` 키(`eyJ...`로 시작하는 아주 긴 문자열)가 있을 수도 있어요. 그걸 써도 똑같이 동작하지만, **2026년 말 지원 종료 예정**이라 새로 시작하는 지금은 `sb_publishable_...` 쪽을 쓰는 게 맞습니다.

> 🔐 이 키가 노출돼도 괜찮은 이유: 이 키는 어차피 브라우저 소스코드에 박혀서 누구나 볼 수 있는 값이에요. 진짜 보안은 STEP 3에서 실행한 SQL의 **RLS 정책**이 담당합니다. 우리 정책은 "누구나 읽기/쓰기 가능"이라 롤링페이퍼에 딱 맞고, 삭제/수정은 아무도 못 하게 막혀 있어요.

---

## STEP 5 — 프로젝트에 값 넣기 (1분)

프로젝트 폴더에 **`.env.local` 파일을 이미 만들어 뒀습니다.** 열어서 `=` 뒤에 붙여넣기만 하세요.

```bash
NEXT_PUBLIC_SUPABASE_URL=https://abcd1234.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_xxxxxxxxxxxx
```

**자주 하는 실수 3종:**

- ❌ `NEXT_PUBLIC_SUPABASE_URL="https://..."` — 따옴표 붙이지 마세요
- ❌ `NEXT_PUBLIC_SUPABASE_URL = https://...` — `=` 앞뒤 공백 넣지 마세요
- ❌ URL 끝에 `/rest/v1` 같은 게 붙어있는 경우 — `.supabase.co` 에서 끊어야 합니다

> `.env.local` 은 `.gitignore`에 걸려 있어서 깃허브에 올라가지 않습니다. 안심하세요.

---

## STEP 6 — 잘 됐는지 확인 (1분)

터미널에서 프로젝트 폴더로 이동한 뒤:

```bash
npm run check:supabase
```

**✅ 성공하면:**
```
✅ 연결 성공! messages 테이블에 현재 0개의 메시지가 있어요.
```

**❌ 실패하면** 스크립트가 원인과 해결법을 한글로 알려줍니다. 대표적인 경우:

| 메시지 | 원인 | 해결 |
|---|---|---|
| `.env.local 에 값이 아직 비어 있어요` | STEP 5 누락 | 값 붙여넣기 |
| `messages 테이블이 없어요` | STEP 3 누락/실패 | SQL Editor에서 다시 Run |
| `API 키가 올바르지 않아요` | 키 복사 실수 | 다시 복사, 앞뒤 공백 확인 |

확인이 끝나면:

```bash
npm run dev
```

`http://localhost:3000` 에서 메시지를 하나 남기고 **새로고침(F5)** 해보세요.
메시지가 그대로 남아있으면 **끝난 겁니다** 🎉
(화면 아래 "지금은 미리보기 모드예요" 문구도 사라져 있어야 합니다.)
